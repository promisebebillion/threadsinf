# Архитектура ThreadFlow

- React/Vite frontend, Express backend, публичные типы в отдельном workspace.
- Только Supabase в схеме `public`; тестовое заполнение отсутствует.
- Текущий режим `browser`: пользователь сам входит в Threads в отдельном браузере. Чистый BrowserContext для каждого подключения отделяет аккаунты от других профилей.
- Попытка подключения принадлежит пользователю и его текущей сессии ThreadFlow, ограничена 15 минутами. Незавершённый вход не сохраняется.
- Подключение требует точного ожидаемого Threads username, действующих cookies и собственного профиля в навигации вошедшего пользователя. Cookies Instagram сами по себе не подтверждают вход в Threads. SMS/checkpoint/блокировка имеют приоритет; ID и username должны совпадать. Состояние проверяется в скрытом новом контексте перед сохранением; ручное окно остаётся открытым.
- Browser storageState шифруется AES-256-GCM и сохраняется в существующее поле SocialAccount.accessToken при provider=browser. Открытие аккаунта восстанавливает новое окно из зашифрованного состояния; API не возвращает cookies клиенту.
- Переподключение проверяет тот же профиль; отключение стирает состояние входа. Сессии платформы остаются HttpOnly, пароли платформы хешируются, данные проверяются по владельцу.
- Текстовая публикация открывает отдельный контекст нужного профиля, проверяет вход и заполняет только форму нового поста. Перед отправкой сохраняется необратимая граница; после неё сбои не повторяются автоматически. Успех требует нового permalink с совпадающими автором, текстом и свежим временем. Рабочий процесс выполняет сохранённое расписание, пока backend работает; по одному посту на профиль с интервалом не менее 8 секунд.
- Карточка различает сохранение сессии и подтверждение текущего входа; показывает результат последней проверки. Открытые окна проверяются чтением без навигации. Окно входа ограничено 15 минутами до сохранения, сохранённое окно не закрывается по этому сроку.
- Код официального Meta Threads API сохранён отдельно от активного способа подключения.

## Проверка

Unit-тесты состояния/шифрования/изоляции/TTL, TypeScript, lint и сборка; настоящие HTTP-сценарии с Supabase и очисткой временных данных. Живой профиль проверяется после ручного входа владельца. Встроенное окно предназначено для локального компьютера backend.
